# --- WebSocket client ----------------------------------------------------
# Discord has no HTTP webhook for regular messages -- a bot only receives
# them by holding open a WebSocket to Discord's own Gateway (see
# channels/discord/gateway.py). httpx does not speak WebSocket, so this is
# the one channel that needs a second client library.
websockets==15.0.1

# --- Encryption --------------------------------------------------------
# SQLCipher backs the per-company encrypted databases. The -binary wheel ships
# a bundled SQLCipher, so no system library or compiler is needed on the VPS.
sqlcipher3-binary==0.6.0
# AES-GCM for wrapping each company's database key.
cryptography==50.0.0

# --- Two-factor authentication -----------------------------------------
# TOTP, the six-digit code an authenticator app produces. Chosen over SMS
# deliberately: an SMS code can be intercepted by a SIM swap, which is a real
# and routine attack against exactly the kind of account this protects, and it
# would also make the platform depend on a paid gateway to let its operator in.
pyotp==2.10.0
# Renders the enrolment QR as an SVG the browser draws inline. No image
# encoder, no temporary file, and the secret never leaves the response.
segno==1.6.6

# --- Channel-specific crypto ---------------------------------------------
# Google Chat's inbound webhook authenticates the caller with a Google-signed
# JWT (see channels/google_chat/webhook.py), and a connecting Chat app
# authenticates its own outbound calls by self-signing one (see channels/
# google_chat/sender.py). `cryptography` above already does the actual RSA
# work underneath; PyJWT is the thin, well-audited layer that builds the
# token shape and, on the inbound side, fetches and caches Google's public
# keys -- reimplementing JWK-to-RSA-key reconstruction by hand is exactly the
# kind of crypto code most likely to hide a subtle bug.
PyJWT==2.14.0

# Instagram (direct login) -- the unofficial channel, not the Meta Graph API
# "instagram" one. `instagrapi` reimplements Instagram's own private mobile
# API (see backend/api/routes/instagram_direct.py, channels/instagram_
# direct/), which is what a plain username and password authenticates
# against instead of a Meta developer app. It brings its own `requests`
# (not this codebase's own choice of HTTP client, only used inside
# instagrapi itself), `curl_cffi` (TLS fingerprinting close enough to a
# real Instagram app to avoid being trivially told apart from one),
# `pycryptodomex` and `PySocks` (proxy support) -- pinned here the same way
# every other dependency in this file is, transitive or not.
instagrapi==3.0.2
requests==2.34.2
curl_cffi==0.16.3
pycryptodomex==3.23.0
PySocks==1.7.1
